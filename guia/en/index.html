Git is a garden

Save every version of your work, try ideas without breaking anything, and bring it all together with your team.

In short

This free guide explains Git through the story of a gardener. Git is a tool that keeps every version of a project, like photos of a garden taken over time. It is useful for people who program, people who work with AI agents, and anyone who wants to stop losing files. Here you will learn six commands (clone, commit, branch, worktree, merge, and push), each with a drawing, a simple explanation, and commands ready to copy. To practice, you just need to have Git installed.

What it is

The gardener's dictionary

Before the commands, the metaphor. Each part of Git has a place in the garden — keep this table handy and the rest is easy.

🌱 Garden = project

The whole project folder, with everything inside it.

🌿 Plants = files

Every file you create, edit, or delete.

📸 Photo = commit

A photo of the whole garden, with a date and a note saying what changed.

🏷️ Label = branch

A name that points to a photo and moves along when you take new photos.

🪴 Flower bed = worktree

Another folder for the same project, so you can work on two things at the same time.

🏡 Greenhouse = remote

The shared copy for the team, for example on GitHub.

How it works

The gardener's 6 steps

This is the daily cycle: you clone once, then repeat commit, branch, merge, and push. Click a step to open its explanation.

1 · Clone→2 · Commit→3 · Branch→4 · Worktree→5 · Merge→6 · Push
Step 1

Clone — Bring the garden home

Clone copies the project and its entire history to your computer.

Step 2

Commit — Take a photo of the garden

Edit, choose what to include, and take the photo. The commit saves it on your computer.

Step 3

Branch — Try a new idea

A branch is a label that moves along with your new commits.

Step 4

Worktree — Two flower beds at the same time

A worktree is another folder for the same project, open on another branch.

Step 5

Merge — Bring the changes together

Merge brings two histories together in a new commit.

Step 6

Push — Share with the team

Push sends your commits to the remote. Now the team can get them.

Cheat sheet

All the commands on one screen

Print it, save it, or keep it open next to the terminal.

git clone <url> gardenbring the project and its history to your computer
git statussee what changed and what is in the staging area
git add .put the changes in the staging area
git commit -m "frase"take the photo: save the version on your computer
git switch -c flowerscreate the flowers label and work on it
git worktree add ../garden-main mainopen another folder, on another branch
git merge flowersbring the flowers branch into the current branch
git push origin maintake your photos to the greenhouse
git fetchdownload the greenhouse's new history without joining it
git pulldownload and join it into your branch

Commit saves at home. Push shares with the team.

The daily cycle

Clone once. After that: commit often, branch for each idea, worktree when you need two things at once, merge to bring them together, and push to share.
